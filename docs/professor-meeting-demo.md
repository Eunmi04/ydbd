# 교수님 미팅용: 4인 가상 택시 운행 시연안

## 이번에 보여줄 수 있는 화면

- 방 찾기·생성, 참여, 준비·탑승 확인, 요금 입력·정산 결과, TEST 크레딧 지갑과 거래 내역.
- 지갑의 월간 동승 횟수·분담액·추정 절약액과 건별 내역 이동. 금액은 기존 완료 정산 기록으로 계산하며 실제 결제 내역이 아니다.
- 현재 앱의 서버 흐름은 **준비 시 TEST 크레딧 예치 → 각 참여자의 요금 확인 → 정산**이다. 아래 개선안의 기사 승인·예치 없는 자동 차감은 아직 구현된 기능으로 시연하지 않는다.

## 제안할 4인 역할과 운행 시나리오

| 시연자 | 역할 | 화면에서 할 일 |
| --- | --- | --- |
| 1 | 방장 겸 승객 | 경로·시간으로 방 생성, 운행 후 요금·증빙 입력 |
| 2 | 승객 A | 방 참여, 운행 정보 확인, 정산 내역 조회 |
| 3 | 승객 B | 방 참여, 운행 정보 확인, 월간 이용 내역 조회 |
| 4 | 가상 택시기사 | 운행 시작·완료와 방장이 입력한 요금 확인 |

제안 흐름: 방 생성 → 승객 참여 및 정산 규칙 동의 → 기사 운행 시작·완료 → 방장 요금 입력 → 기사 요금 확인 → 서버가 분담액 계산·TEST 크레딧 기록 → 개인별 월간 요약·건별 상세 조회. 동승객에게 매번 승인 버튼을 요구하는 대신 이의 제기 경로를 둔다. 이의가 있으면 자동 정산을 보류한다.

## 팀에서 확정할 질문

1. 준비 단계의 예치를 없애고 정산 완료 시 TEST 크레딧을 바로 차감할지. 차감 시 잔액 부족이면 정산을 보류할지.
2. 방장과 기사 양쪽 확인이 필요한지, 확인할 요금·운행 데이터는 무엇인지.
3. 승객의 정산 규칙 동의 시점과 이의 제기 가능 시한.
4. ‘절약액’ 비교 기준. 현재 화면은 같은 요금의 택시를 혼자 탔다고 가정한 **추정치**를 사용한다.

정효민이 공유 DB와 마이그레이션을 대표 관리한다. 정은미는 지갑·원장·월간 요약과 자동 차감 계약을, 이예빈은 요금·승인·이의를, 김정서는 방·운행 흐름을 담당하는 안으로 조율한다. 실제 택시비는 이용자가 기사에게 직접 결제하며 앱은 실제 돈을 충전·송금·환급하지 않는다.
